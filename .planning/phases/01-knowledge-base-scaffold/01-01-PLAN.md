<objective>
Create the Phase 1 filesystem scaffold for the Modernist Cooking Knowledge Base and update the user-facing orientation docs so future agent sessions can safely distinguish raw evidence, source summaries, compiled wiki content, indexes, outputs, and health reports.
</objective>

<context>
Read before starting:

- `.planning/phases/01-knowledge-base-scaffold/01-CONTEXT.md`
- `.planning/phases/01-knowledge-base-scaffold/01-RESEARCH.md`
- `.planning/REQUIREMENTS.md`
- `.planning/ROADMAP.md`
- `AGENTS.md`
- `README.md`

This is a local markdown knowledge base, not an app. There is no frontend, database, server, or source conversion automation in scope.
</context>

<must_haves>
## Requirements

- Cover `SCF-01`: create the `knowledge/` folder structure with separate areas for raw sources, source summaries, wiki articles, indexes, outputs, and health reports.
- Cover `SCF-02`: ensure `AGENTS.md` explains source handling, compile rules, evidence preservation, index updates, and health checks.
- Cover `SCF-03`: ensure the root `README.md` explains the knowledge base purpose and basic source-ingest workflow.
- Cover `SRC-01`: create a raw source inbox where the user can place converted markdown sources and notes without conversion automation.
- Cover `SRC-04`: make raw evidence distinct from compiled wiki files and explicitly protect raw files from compile-pass rewrites.
- Cover `IDX-01`: create an index entry point that tells future sessions what to read first.

## Locked Decisions From CONTEXT.md

- `D-01`: Create the full practical v1 scaffold immediately, not just the six top-level folders.
- `D-02`: Include `knowledge/wiki/concepts/`, `techniques/`, `ingredients/`, `equipment/`, `recipes/`, and `safety/`.
- `D-03`: Include `knowledge/raw/inbox/` as the default raw source landing zone.
- `D-04`: Include `knowledge/health/reports/`.
- `D-05`: Use lightweight placeholders: README files where they clarify boundaries, `.gitkeep` where empty folders must exist in git.
- `D-06`: Treat `knowledge/raw/` as the FPF evidence layer and do not rewrite raw sources during compile or cleanup passes unless explicitly asked.
- `D-07`: Treat `knowledge/sources/` and `knowledge/wiki/` as derived episteme layers with source traceability.
- `D-08`: Make the raw-vs-derived distinction visible through scaffold docs.
- `D-09`: Make `knowledge/indexes/README.md` a practical orientation guide for future agent sessions.
- `D-10`: Acknowledge planned-but-not-yet-created indexes honestly.
- `D-11`: Preserve existing `AGENTS.md` direction and strengthen only concrete Phase 1 scaffold rules.
- `D-12`: Keep the root README readable for the user while giving future agents enough orientation.

## FPF Guardrails

- Preserve Strict Distinction: raw evidence, source summaries, wiki synthesis, outputs, and health reports are separate roles.
- Preserve the Evidence Graph: future important claims need paths back to source summaries or raw sources.
- Apply Ontological Parsimony: do not add databases, vector stores, scripts, templates, or UI work in this plan.
</must_haves>
